# RiskPilot REST API

Базовый URL: `http://localhost:8080`. JSON в UTF-8. Суммы — тыс. ₽. Аутентификация в локальном MVP отсутствует. CORS для сторонних сайтов не включён.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/meta` | Название, категории, значения по умолчанию, лимит рисков |
| GET | `/api/risks` | Список `{id,input}` |
| POST | `/api/risks` | Создать риск, HTTP 201 |
| PUT | `/api/risks/{id}` | Изменить риск с оптимистической версией |
| DELETE | `/api/risks/{id}` | Удалить риск, HTTP 204 |
| GET | `/api/analysis` | Полный расчёт с настройками по умолчанию |
| POST | `/api/analysis` | Полный расчёт с указанными ограничениями |
| GET | `/api/model` | Метрики, коэффициенты, нормализация, разбиение |
| GET | `/api/knowledge` | Каталог шести правил |
| GET | `/api/history.csv` | Выгрузка синтетической истории |
| GET | `/actuator/health` | Проверка здоровья приложения и соединения с БД |

## Создание и редактирование риска

```json
{
  "title": "Срыв поставки API",
  "category": "SUPPLIER",
  "owner": "Анна Смирнова",
  "loss": 900,
  "delayDays": 18,
  "urgency": 5,
  "features": {
    "complexity": 0.8,
    "experience": 0.6,
    "workload": 0.85,
    "dependencies": 8,
    "volatility": 0.6,
    "reliability": 0.25
  },
  "version": 0
}
```

Категории: `TECHNICAL`, `PEOPLE`, `SCHEDULE`, `SUPPLIER`, `REQUIREMENTS`, `SECURITY`. При создании version устанавливается в 0. При PUT передайте версию последнего чтения; успешное изменение увеличит её. Повторная отправка старой версии даёт HTTP 409. Одновременное создание ограничивается блокировкой строки метаданных, максимум 14 рисков. Пустой реестр поддерживается и после перезапуска не заполняется заново.

## Расчёт

```sh
curl -sS -X POST http://localhost:8080/api/analysis \
  -H 'Content-Type: application/json' \
  -d '{"budget":300,"capacityDays":25,"dayCost":25}'
```

Неуказанные поля получают значения по умолчанию. Для произвольной модели передайте `matrix` (4×4 взаимно обратная матрица) и `scenarios` (ровно три объекта `name`, `probability`, `probabilityFactor`, `lossFactor`, сумма вероятностей 1). Полный образец тела запроса содержится в поле `request` файла `demo-analysis.json`.

Ответ объединяет `ahp`, `risks` (прогноз, AHP, вклад признаков, правила), `plan`, `uncertainty` (сценарии, сравнение стратегий, имитация), `recommendations`, `model`, `knowledgeRules`, `warnings`. Это единый согласованный снимок реестра в read-only транзакции REPEATABLE READ. Расчёт не изменяет исходные риски и не сохраняет настройки бюджета; экспорт JSON содержит фактически использованные настройки.

## Ошибки

`400 {"error":"…"}` — неверный JSON, неизвестная категория/поле, значение вне диапазона, сумма вероятностей не равна 1, CR > 0,10, превышение 14 рисков. `404` — отсутствующий риск. `409` — конфликт версии. В интерфейсе при неудачном пересчёте показан предыдущий результат с явным сообщением об ошибке.

## ML лаборатория

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/model/artifact` | Текущая обученная модель JSON с версией и всеми параметрами |
| GET | `/api/model/versions` | Сохранённые версии с источниками, датами и метриками |
| POST | `/api/model/train` | Multipart поле `file` с CSV; обучить, сохранить и активировать |
| POST | `/api/model/reset` | Обучить новую учебную версию на синтетической истории |
| POST | `/api/model/versions/{id}/activate` | Вернуться к сохранённой версии |
| POST | `/api/model/predict` | Объект Features → вероятность, класс, порог, версия и вклады |

CSV: 90–5000 записей, ≥30 проектов, фиксированный заголовок и числовые поля. До 1 МБ; оба класса должны присутствовать в каждой части группового разбиения. Недостоверность, утечку будущих признаков или повторное использование test внешний валидатор должен контролировать отдельно. Ошибка проверки/обучения не изменяет активную модель. В БД сохраняются параметры и CSV; повторный старт восстанавливает текущую версию.

```sh
curl -fsS -F 'file=@history.csv' http://localhost:8080/api/model/train
curl -fsS http://localhost:8080/api/model/artifact -o riskpilot-model.json
```

## Пользовательские мероприятия

`GET /api/risks/{id}/measures` возвращает фактические альтернативы: собственные либо начальные шаблоны. `PUT` того же пути заменяет набор из одной или двух мер. В теле — массив объектов `{title,cost,days,reduction}`. Стоимость 0–100000, дни 0–365, reduction 0–1. Мера уменьшает тяжесть последствий. `DELETE` удаляет собственные оценки и возвращает шаблоны. Поле `availableMeasures` общего анализа содержит использованный каталог; `modelVersion` — идентификатор и параметры применённой модели.

## История решений

`POST /api/decisions` принимает `{title,request}`. Сервер заново рассчитывает решение и сохраняет полный неизменяемый снимок с рисками, мерами и моделью. `GET /api/decisions` возвращает краткий список; `GET /api/decisions/{id}` — полный снимок; `DELETE` удаляет сохранённый снимок. `GET /api/decisions/compare?left=UUID&right=UUID` сравнивает два сохранённых решения: полную стоимость, чистый эффект, бюджет, добавленные и исключённые меры. Разности — right минус left. Сравнение описательное: если изменились данные или модель, разница не является изолированным эффектом бюджета.

## Расписание ML

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/model/retraining` | Настройки, следующий запуск, очередь, последние 50 записей журнала |
| POST | `/api/model/dataset` | Multipart `file`: проверить CSV и сохранить в очередь без обучения |
| POST | `/api/model/retraining/run` | Немедленно выполнить процесс планировщика с фильтром качества |

`POST /api/model/train` по-прежнему явно обучает и активирует CSV, одновременно обновляя очередь. Автоматический процесс может вернуть REJECTED, SKIPPED или FAILED с объяснением, сохранив активную модель. HTTP 200 означает завершённый запуск; итог находится в поле `status`.
